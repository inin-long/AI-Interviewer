# 冷静、专业、克制的 AI 面试工作台

它应该更像一款面向程序员的桌面生产力工具，而不是普通聊天软件、招聘管理后台或强调“未来感”的 AI 展示页面。

视觉关键词可以确定为：

> 专业、专注、理性、轻量、可信、技术感、低干扰。

原始需求里同时包含长时间对话、倒计时、流式生成、代码编辑、文档处理、评分报告和多页面数据管理，因此 UI 必须既能承载高密度信息，又不能让用户在面试过程中分心。

------

## 1. 整体视觉定位

建议采用“现代桌面工作台”风格：

- 大面积中性色背景
- 清晰的边框和层级
- 适度紧凑的信息密度
- 少量蓝紫色强调 AI 能力
- 主要依赖排版、留白和分组，而不是大量卡片和阴影
- 不使用赛博朋克、霓虹光效、大面积渐变
- 不把所有页面都设计成仪表盘

整体感觉可以接近：

- 专业 IDE 的稳定感
- Linear 一类工具的清晰层级
- Notion 文档区域的阅读感
- 现代 Windows 桌面应用的操作习惯

但不要完全模仿某一个产品。

# 2. 推荐的颜色体系

## 2.1 明亮主题作为默认主题

主背景不要用纯白，而是使用轻微偏冷的浅灰：

```
应用背景       #F6F7F9
主要表面       #FFFFFF
次级表面       #F9FAFB
悬浮背景       #F1F4F8
普通边框       #E4E7EC
强调边框       #CDD3DC
主文字         #171A21
次级文字       #5F6673
弱化文字       #9299A6
```

## 2.2 品牌主色

推荐偏沉稳的蓝紫色，而不是过亮的科技蓝：

```
主色           #4F63D9
悬停主色       #4356C6
按下主色       #394AB1
浅色背景       #EEF0FF
```

蓝紫色能够同时表达：

- 技术
- AI
- 理性
- 专业

但页面中主色占比应控制在 10% 左右。

## 2.3 状态色

```
成功           #27845B
成功背景       #EAF7F0

警告           #B26A15

错误           #C53B46

信息           #3478B8

```

状态颜色只用于：

- 连接状态
- 文档解析状态
- 倒计时警告
- 任务失败
- 面试状态
- 评分提示

不要用于大面积装饰。

# 3. 暗色主题

暗色模式不能简单反转颜色，应单独定义表面层级：

```
应用背景       #111318
主要表面       #191C23
次级表面       #20242D
悬浮背景       #292E38
普通边框       #303641
主文字         #EEF0F4
次级文字       #AEB4C0
弱化文字       #767E8D
主色           #8290F2
```

暗色模式尤其适合长时间面试和代码编辑。原需求已经明确要求浅色、深色主题运行时切换，因此两个主题都应视为正式设计，而不是后期简单补色。

# 4. 排版风格

## 普通文字

Windows 默认建议：

```
Segoe UI
Microsoft YaHei UI
sans-serif
```

英文、数字和界面文本优先使用 Segoe UI，中文使用系统回退。

## 代码字体

```
Cascadia Mono
Consolas
monospace
```

## 字号层级

```
页面主标题       24px / SemiBold
模块标题         18px / SemiBold
卡片标题         15px / SemiBold
正文             14px / Regular
辅助文字         12px / Regular
状态标签         12px / Medium
代码             13px
```

不建议使用大量 28～36px 的大标题。它是桌面工具，不是营销网站。

------

# 5. 组件形态

## 圆角

整体采用中等偏小圆角：

```
输入框和按钮      7px
普通卡片          10px
对话框            12px
状态标签          999px
```

不要使用大量 16～24px 的超大圆角，否则会显得过于移动端化。

## 阴影

常规页面以边框分层，尽量不用阴影。

仅以下内容可以使用轻阴影：

- 弹窗
- 下拉菜单
- 悬浮草稿窗口
- Tooltip
- 临时浮层

## 图标

建议使用统一的细线图标：

- 默认 18px
- 紧凑操作 16px
- 页面空状态 32～40px
- 线宽保持一致
- 不在正式界面使用 Emoji 作为功能图标

# 6. 主框架布局

当前确定的是单主窗口和永久左侧导航，因此建议结构为：

```
┌─────────────────────────────────────────────────────────────┐
│ 顶部栏：页面标题 / 全局状态 / AI 连接状态 / 用户操作         │
├──────────────┬──────────────────────────────────────────────┤
│              │                                              │
│ 左侧导航     │ 主内容区域                                   │
│              │                                              │
│ 首页         │                                              │
│ 面试方案     │                                              │
│ 面试记录     │                                              │
│ 简历         │                                              │
│ 知识库       │                                              │
│              │                                              │
│ 设置         │                                              │
│ 用户入口     │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

建议尺寸：

```
导航栏展开宽度       216px
导航栏收起宽度        64px
顶部栏高度            56px
页面左右内边距        28px
页面上下内边距        24px

最小支持窗口宽度    1024px
```

左侧导航不要设计得过宽，也不要在里面堆叠统计数据。它只负责导航。

导航项建议最终收敛为：

```

面试记录
简历
知识库
设置
```

“报告”不需要独立一级导航，报告应当从面试记录进入，否则信息架构会重复。

# 7. 首页风格

首页不应做成铺满统计卡片的后台仪表盘。

更适合采用“行动导向首页”：

```
早上好，Mahoo
准备进行一次针对性模拟面试吗？

[开始面试]   [创建面试方案]
```

下面只展示三个区域：

1. 未完成的面试
2. 最近使用的面试方案
3. 最近一次面试结果

状态概览可以是一条横向信息带：

```
简历 3 份 · 知识库 12 个文档 · AI 服务正常
```

首页的首要目标不是展示数据，而是帮助用户快速进入面试。

# 8. 面试方案页面

建议采用列表为主，而不是一屏多个大卡片。

顶部：

```
面试方案                              [新建方案]
保存常用岗位、简历和面试规则
```

列表行：

```
Java 后端高级面试
Java 后端工程师 · 高级 · 45 分钟 · Java 后端简历
重点：Spring、数据库、项目深挖

最后使用：昨天                       [开始] [编辑] [更多]
```

每行高度约 88～104px。

新建和编辑方案建议使用独立内容页，而不是窄小弹窗，因为字段包括：

- 方案名称
- 岗位名称
- JD
- 难度
- 简历
- 时长
- 题目数量
- 自定义规则

推荐双栏布局：

```
左侧：配置表单
右侧：实时方案摘要
```

底部固定：

```
[取消]                         [保存方案] [保存并开始]
```

# 10. 面试页面：最核心的视觉设计

面试页应该进入一种独立的“专注模式”。

进入面试后：

- 左侧导航自动收起到 64px，或完全隐藏
- 顶部只保留必要信息
- 减少所有非面试功能入口
- 不显示首页导航和统计信息

推荐结构：

```
┌───────────────────────────────────────────────────────────────┐
│ Java 后端高级面试    技术深挖 · 第 7 题     23:18    [暂停]   │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
├──────────────────────────────────────┬────────────────────────┤
│                                      │ 当前面试               │
│ 对话记录                             │                        │
│                                      │ 阶段                   │
│ AI 问题                              │ 技术深挖               │
│                                      │                        │
│ 用户回答                             │ 已完成 7 / 15           │
│                                      │                        │
│ AI 追问                              │ Token 8,240             │
│                                      │                        │
│                                      │ 使用资料               │
│                                      │ Java简历.pdf            │
├──────────────────────────────────────┴────────────────────────┤
│ [回答输入区域                                      ]          │
│ [代码编辑器] [草稿]                         Ctrl+Enter [发送] │
└───────────────────────────────────────────────────────────────┘
```

右侧信息栏建议可折叠，宽度约 260px，内容只包含：

- 当前阶段
- 问题进度
- 剩余时间
- 当前简历
- Token 状态
- 本轮引用资料

不要展示大量调试信息或 Agent 节点名称。

## 对话风格

不要设计成微信式左右气泡。

更适合文档流式布局：

```
AI 面试官
问题正文……

你
回答正文……
```

不同角色依赖：

- 头像或角色图标
- 标签
- 背景色
- 左侧竖线

进行区分。

AI 消息使用白色或主要表面；用户回答使用轻微主色背景。

每条消息右上角在悬停时显示：

- 复制
- 重新生成
- 定位
- 更多

原需求中的流式输出、复制、终止生成、重新生成和多行输入，意味着输入区与消息操作必须清晰但低干扰。

# 11. 输入区域

输入区建议像专业编辑器，而不是普通聊天框：

```
┌───────────────────────────────────────────────────────┐
│ 输入你的回答……                                       │
│                                                       │
│                                                       │
├───────────────────────────────────────────────────────┤
│ + 代码回答   草稿                       Ctrl+Enter 发送 │
└───────────────────────────────────────────────────────┘
```

规则：

- 最小高度 96px
- 最大高度约 240px
- 超出后内部滚动
- 输入时自动扩展
- 清晰显示快捷键
- 生成中发送按钮切换为“停止生成”
- 网络失败时输入内容不能消失

------

# 12. 代码编辑器

代码编辑器应与面试输入区融为一体，通过展开面板出现。

样式接近轻量 IDE：

- 深色编辑器可独立于应用主题
- 行号区域
- 当前行高亮
- 语言选择
- 字号缩放
- 复制按钮
- 不显示运行按钮，避免误导

```
Java                                           [复制] [收起]
──────────────────────────────────────────────────────
 1  public class LruCache {
 2
 3  }
```

代码编辑器是辅助回答工具，不应成为页面主视觉。原需求明确不提供本地沙箱运行，因此 UI 中也不应出现类似“运行”“测试通过”等暗示。

------

# 13. 报告页面

报告页应采用“正式评估文档”风格，而不是数据大屏。

推荐布局：

```
┌──────────────────────┬───────────────────────────────────────┐
│ 报告目录             │ Java 后端高级面试报告                 │
│                      │                                       │
│ 综合评价             │ 82 / 100                              │
│ 能力评分             │                                       │
│ 优势                 │ 雷达图 + 维度条                       │
│ 不足                 │                                       │
│ 学习建议             │ 综合评价正文……                       │
│ 面试记录             │                                       │
└──────────────────────┴───────────────────────────────────────┘
```

顶部评分区可以使用：

- 一个综合分数
- 一个雷达图
- 五个横向评分条

不要同时堆叠大量饼图、折线图和仪表盘。

评分条目应可以点击定位至对应问答，原始需求已经明确报告与对话需要联动。

薄弱点使用标签，但不要做随机大小、随机旋转的传统“标签云”。更适合整齐排列：

```
Redis 一致性
JVM 内存模型
分布式事务
系统容量估算
```

# 14. 设置页面

设置页采用传统桌面设置布局：

```
设置

常规
  主题
  窗口行为
  输入快捷键

AI 服务
  Base URL
  API Key
  Chat Model
  Embedding Model
  [测试连接]

网络
  代理设置

数据
  数据目录
  日志目录
```

不要把每个设置项设计成一张卡片。

使用：

- 分组标题
- 描述文字
- 表单行
- 分隔线

连接测试状态应在字段附近显示：

```
● 已连接
● 连接失败
● 未检测
```

而不是每次启动都弹出成功弹窗。成功状态适合静默展示，只有失败时需要明显提醒。

------

# 15. 动效原则

动效只能帮助理解状态，不能为了“AI 感”而存在。

推荐时长：

```
按钮状态          100–140ms
页面内容切换      160–200ms
侧栏展开收起      180–220ms
弹窗进入          160ms
Toast             180ms
```

适合使用的动效：

- 流式文本光标
- 加载骨架
- 进度条平滑变化
- 当前阶段切换
- 面板展开收起
- 状态标签淡入

不适合：

- 大面积粒子背景
- 呼吸光边框
- 鼠标跟随光效
- 长时间渐变动画
- 整页滑入滑出
- 每个卡片悬停上浮

------

# 16. 响应式与窗口缩放

这是 Windows JavaFX 应用，不需要像网页一样覆盖所有尺寸，但必须定义窗口断点。

建议：

## 大窗口：≥ 1280px

- 左侧导航展开
- 面试页显示右侧信息栏
- 表格完整字段

## 中窗口：1024～1279px

- 左侧导航可收起
- 右侧信息栏默认折叠
- 次要表格字段隐藏

## 小窗口：< 1024px

- 设置最小窗口宽度，不继续压缩
- 不尝试适配手机布局

原始需求要求适应不同 Windows 分辨率，因此重点是合理伸缩和信息降级，而不是实现移动端响应式。

------

# 17. 最终风格总结

最终视觉方向可以定义为：

> 一套以浅灰白为基础、蓝紫色为强调色、列表和文档布局为主、卡片为辅的现代专业桌面工作台。普通管理页面保持清晰高效，面试页面进入沉浸专注模式，报告页面呈现正式评估文档质感。

最重要的三个判断标准是：

1. **像专业工具，而不是 AI 概念演示。**
2. **面试时安静专注，管理时清晰高效。**
3. **信息密度足够，但绝不堆叠卡片、图表和装饰。**
